    多语言

    双字典、取词原语与降级路径

    Cinder 的组件文案全部经过一张字典取词，字典随 core 域一起分发，零依赖、无构建期编译、file:// 直接可用。

    • 原语位置：packages/base/src/primitives/i18n.js
    • 挂载点：window.Cinder.Primitives.i18n
    • 内置语言：zh-CN（默认）、en
    • 一致性闸门：npm run check:i18n（8 条断言，见文末）
    • 验收脚本：node scripts/acceptance-i18n.mjs（31 条断言）
    • 演示页：demos/i18n.html

    一、定位与边界

    做 不做
    组件产生的用户可见文案（aria-label、空态、按钮文字、相对时间） 业务内容文案（由使用方自己维护）
    运行期切换语言，静态标记自动刷新 复数规则（one/other）、性别、语序重排
    缺字典时回落到调用处的中文兜底 内置 RTL 布局翻转
    允许注册第三方语言并局部覆盖 编译期抽取字典、按 key 摇树

    二、字典结构与 key 规范

    key 一律 组件.语义，小驼峰语义段；同一语义在两种语言下 key 相同。

    DICTS = {
  "zh-CN": { "datepicker.today": "今天", "otp.digit": "第 {n} 位验证码" },
  "en":    { "datepicker.today": "Today", "otp.digit": "Digit {n}" },
}
    • 插值统一 {name} 语法，占位符名跨语言必须一致（闸门第 3 条）。
    • 禁止在 key 里嵌语言或版本号。

    三、API

    成员 签名 说明
    t t(key, fallback?, vars?) 按当前语言取词，缺失时用 fallback，再缺失返回 key 本身
    tIn tIn(locale, key, fallback?, vars?) 按显式语言取词（组件透传了 locale 参数时用）
    setLocale setLocale(tag, opt?) 归一化并切换语言，写回 <html lang>，派发 cin:localechange
    getLocale getLocale() 当前生效语言
    register register(tag, dict) 注册/合并字典，后注册的覆盖先注册的同名 key
    apply apply(scope?) 按 data-i18n / data-i18n-aria 刷新指定范围
    locales locales() 已注册语言列表
    onLocaleChange onLocaleChange(fn) 订阅切换事件，返回取消函数
    DICTS DICTS 字典本体（只读约定，勿原地改） 
    const i18n = Cinder.Primitives.i18n;
i18n.t("otp.digit", null, { n: 3 });        // 第 3 位验证码
i18n.tIn("en", "copy.done");                // Copied（不改当前语言）
i18n.setLocale("en");                       // → "en"，<html lang="en">
i18n.register("ja", { "copy.done": "コピー済み" });
i18n.apply(document.querySelector("#panel")); // 只刷新局部

    语言归一化：zh / zh-CN / zh-Hans-CN 归一为 zh-CN，en-US / en-GB 归一为 en；未注册语言回落 zh-CN（setLocale("fr") 返回 "zh-CN"）。

    四、静态标记

    无需写 JS 就能吃到多语言：

    <p data-i18n="tree.noMatch">没有匹配的节点</p>
<button data-i18n-aria="copy.done" aria-label="已复制">复制</button>
    • data-i18n 覆盖 textContent，data-i18n-aria 覆盖 aria-label。
    • 初始加载与每次 setLocale 后自动刷新；apply(scope) 可手动刷新动态插入的节点。
    • 元素内的中文原文即兜底，字典缺失时保留原文。

    五、组件侧约定

    • 每个 behavior 顶部声明取词助手，二参为中文兜底：
    const tr = (k, f, v) =>
  C.Primitives && C.Primitives.i18n
    ? C.Primitives.i18n.t(k, f, v)
    : v
      ? f.replace(/\{(\w+)\}/g, (m, key) => (v[key] != null ? v[key] : m))
      : f;
    • 兜底文案必须与 zh-CN 字典逐字一致（闸门第 4 条），否则会出现"字典改了、兜底没改"的分叉。
    • 取值只能走 tr() / tIn()，不得直接读 DICTS。
    • 禁止用文案当作选择器：timepicker 原先把 aria-label="分钟" 当查询条件，已改为 data-col="minute"。凡新增代码都按"文案可翻译、结构用 data 属性"的原则写。
    • 组件若自身接受 locale 参数（如 format.js），用 tIn 取词，不读全局语言。

    六、降级策略

    场景 行为
    只加载分域包（无 core） tr() 回落中文兜底，且仍按 {name} 插值，不会漏出占位符
    字典缺 key 用调用处 fallback；再缺用 key 本身（不抛错、不空白）
    未注册语言 回落 zh-CN
    新语言只翻了一半 缺的 key 回落 zh-CN，其余照常

    七、一句话记牢的两条纪律

    1. 新增任何用户可见文案，必须同时补 tr() 兜底与两套字典，否则 npm run check:i18n 直接失败。
    2. 运行时切换语言不回溯已渲染组件：setLocale 只刷新静态标记与后续取词；已生成的面板（如已打开的 timepicker 列名）需要重新 init 或刷新页面才会换语言。这是刻意取舍——避免每个组件都维护"重渲染"路径。

    八、闸门 npm run check:i18n

    # 断言 拦的是什么
    1 原语可加载并暴露 DICTS 语法错、挂载点丢失
    2 内置 zh-CN 与 en 两套字典 漏建语言
    3 源码存在 i18n 调用点 改造被回滚成硬编码后仍"通过"
    4 调用点 key 均被 zh-CN 覆盖 漏译（新增 tr() 忘加字典）
    5 两语言 key 集合完全一致 半成品翻译、孤儿 key
    6 两语言插值占位符一致 {n} / {total} 错位
    7 调用点中文兜底与 zh-CN 逐字一致 字典与兜底分叉
    8 组件源码无裸中文用户文案 新写文案绕过 tr()，逐文件逐行报位置
