    视觉基线

    像素回归阈值与更新纪律

    状态：已落地（基础设施第 18 项 ◐ → ●）。51 个演示页全量快照，固定环境渲染，像素比对阈值 0.2%。

    1. 为什么需要它

    现有 50 组验收脚本是结构性断言：类名存在、变量有定义、状态选择器齐备、demo 含某个节点。它们能守住"该有的都有"，守不住"看起来变了"——改一条 gap、动一个 border-radius、把断点从 720 挪到 768，断言全绿，界面已经走形。

    视觉回归补的就是这一层：同一份 HTML，在同一视口下渲染出的像素必须与基线一致。

    2. 命令

    命令 作用 耗时
    npm run visual 生成 / 更新全部基线（51 页） 约 95s
    npm run visual:check 全量比对（发版前 / CI） 约 90s
    node scripts/visual-baseline.mjs --only icons thinking 只处理名字含关键字的页 按页数
    node scripts/acceptance-all.mjs visual 验收批内的快速档（8 个关键页） 约 15s

    acceptance-all 只跑 8 个关键页（icons / thinking / tool-chips / approval-card / base / overlay / skins / erp-dashboard），避免每次全量验收多花 90 秒；改样式后仍应手动跑一次全量。

    3. 固定条件（改了就失去可比性）

    项 值 原因
    视口 1280 × 900，deviceScaleFactor: 1 高分屏缩放会引入亚像素差
    动画 截图前注入 animation/transition: none，animations: "disabled" 转圈、脉冲类组件帧位置不确定
    减少动效 reducedMotion: "reduce" 强制走静止分支
    字体 等 document.fonts.ready 字体回退会整页位移
    file:// 权限 --allow-file-access-from-files 图标走 mask 引用 icons/*.svg，否则被 CORS 拦成空块
    抖动等待 120ms 让布局稳定，不掩盖真实差异

    4. 阈值与产物

    • 差异像素比例 > 0.2% 判失败（THRESHOLD）。
    • 尺寸变化单独报错，不走比例比较——页面变高变矮是最常见的真回归。
    • 基线：tests/visual/baseline/<页名>.png（入 git，共 5.7 MB / 平均 119 KB 一页）。
    • 差异图：tests/visual/diff/<页名>.diff.png（不入 git，每次比对重算）。

    5. 更新纪律

    1. visual:check 失败时先看 diff 图，判断是"我想要的改动"还是"意外回归"。
    2. 确认是预期改动，才跑 npm run visual 覆盖基线，并在同一次提交里说明改了哪几个页、为什么。
    3. 禁止在断言失败的情况下顺手更新基线——那等于把回归洗白。这条与预算基线的纪律同源（见 CONTRIBUTING.md 的「预算纪律」）。
    4. 新增演示页必须同时补基线，否则 --check 会报缺基线。

    6. 已知边界

    • 跨机器字体不同会带来整体抖动；阈值 0.2% 能吸收小差异，但换字体的环境建议重建基线。
    • 含时间戳、随机数、滚动位置的页面天然不稳定，这类页面不要纳入基线。
    • 快照只覆盖浅色 + 桌面视口；深色与窄屏靠 skins.html 与人工回归，未做双份基线。
    • 基线是二进制，diff 不可读；配合 CHANGELOG 的说明才能追溯意图。 （内容由AI生成，仅供参考）
