    新组件的四段式契约写法

    每个组件在 packages/base/src/intents/<组件名>.md 写一份。文件名必须与 packages/base/src/components/<组件名>.css 同名。 build.mjs --check 会校验：缺文件且不在 intent-allowlist.json 豁免名单 → 构建失败；已有文件却仍挂白名单 → 同样失败（白名单只减不增）。 本文件的四个段落就是四段硬约束，缺任一即视为契约不完整。

    一、边界（必填，写实）

    • 负责：这个组件在视觉与行为上承诺做到的事，3~6 条，必须能在 CSS/JS 里找到对应实现。
    • 明确不负责：3~5 条"容易被误用为本组件职责、实际不属于"的事项，并指明应由谁承担（原生能力 / 宿主应用 / 其他组件 / 平台 API）。

    判断标准：若一件事写"不负责"，就必须能回答"那谁负责"。写不出承接方的，说明它其实属于本组件。

    二、状态机与失败态（必填）

    • 列出命名的状态属性及取值：data-state / data-cin-status / data-invalid / data-loading / data-open 等，取值必须与源码一致。
    • 明确失败态：空数据、加载中、加载失败、校验不通过、禁用、权限不足，各自落到哪个属性、哪段文案位、是否可见。
    • 明确状态转移禁令：例如"error 态不得直接跳到 done，须经 loading"、"关闭动画期间不得重入"。

    三、可访问性（必填）

    • 语义与角色：用了哪些原生元素、哪些 role / aria-* 属性，谁是可聚焦主体。
    • 键盘：列出必须支持的按键与行为（Enter / Space / Esc / 方向键 / Home / End / Tab 顺序）。
    • 焦点：打开与关闭后焦点落点、是否焦点陷阱、aria-activedescendant 或 roving tabindex 的方案。
    • 对比度与动效：正文对比度下限、prefers-reduced-motion 下的降级行为。

    四、AI 选型提示（必填）

    • 什么时候选它：2~3 条触发场景，用业务语言而非技术语言描述。
    • 什么时候别选它：指向替代组件（写具体组件名）。
    • 最小正确用法：一段可直接复制的 HTML 骨架，属性齐、不依赖 JS 也能读。
    • 常见误用：2~3 条，写"错在哪、会坏什么"。

    五、写作约定

    约定 说明
    篇幅 精写 ≤60 行；骨架 ≥15 行且"边界"段必须写实
    事实来源 只能写 CSS/JS 里查得到的东西，禁止想象未实现的属性或 API
    禁止复制 不做 CSS 类名的二次罗列，只写承诺与禁忌
    与 moments 互引 需要示例数据时引用 moments/，不在此重复贴大段 HTML
    更新时机 组件行为变更必须同批更新 intent.md，否则视为契约过期
