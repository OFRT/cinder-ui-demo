    图标库方案

    一个真源三产出的取舍

    状态：待确认。本文件只给方案与实测数据，确认后才落代码。 2026-11-02 编制。对应能力矩阵基础设施 #10「图标库」。

    1. 现状（实测，不是估算）

    事实 数据
    图标资产 0 个 SVG 文件（find -name "*.svg" 返回空）
    现有图标容器 .cin-icon + `data-size="sm
    现有图标实现方式 8 处 data URI 内联 SVG（fileinput / disclosure / option-group / details / controls / copytarget），各写各的，viewBox 有 16 也有 24，线宽不统一
    兜底手段 demo 里用字符 ⌕ 顶替图标
    组件中的图标位 搜索框、下拉箭头、折叠箭头、勾选框、复制按钮、上传区、轮播箭头、分页、结果页、空态、通知条等

    核心问题：不是"没有图标"，而是同一批语义（箭头/勾/叉/上传）在不同组件里被重复手绘了 8 次，形状与线宽互不相同。所以这不是"补一套图"，是"建一个唯一真源"。

    2. 目标与边界

    要做的：给 Cinder 一份可被 60 个组件共同引用的图标真源，形状统一、许可清晰、体积可控、可按需单取。

    明确不做（写出来避免范围蔓延）：

    不做 理由 / 承接方
    品牌 logo / 插画 / 空态插图 需专门绘制，走设计资源，不在图标库范围
    多字重（线框/实心/双色）三套并行 首版只做 1.75–2px 单一描边；实心态用 CSS 填充或后续增量
    图标搜索页 / 在线浏览站 属于文档站（基础设施 #4），图标库只交付资产与清单
    Figma 组件库同步 基础设施 #19，独立评估
    自研图标编辑器 不在范围

    3. 三条路线对比（含实测体积）

    体积数据来自本轮真机拉取 104 个 Lucide 图标并 sprite 化后实测。

    A. Lucide 单一真源 B. 自绘全套 C. 现成图标字体（iconfont）
    许可 ISC（MIT 等价，可商用，需留版权声明） 自有 多为 OFL/商业授权混杂
    起步成本 低（拉取 + 清洗 + 校验） 高（104 个 × 逐个对齐网格，约 15–20 人日） 低（下载字体）
    风格可控 中（24 网格、stroke 2、round 端点，几何感强） 高 低（字体渲染不可控、无 currentColor 渐变）
    体积（104 个） sprite 原始 20.3KB / gzip 4.9KB，均摊 48B/图标 相近（路径数据量取决于简化程度） 字体文件通常 20–60KB，且全量加载
    渐进增强 / 无 JS 原生 <use>，无 JS 也能显示 同 纯 CSS，但字体阻塞首屏
    可单文件拷贝 是（sprite 一个文件 / 单图标文件） 是 否（字体二进制）
    后续扩图标 直接补文件 每加一个都要画 需重新生成字体（缓存失效）
    风险 与既有 16 网格 data URI 需视觉对齐 工期 与"零依赖、可读源码"原则冲突

    推荐 A，理由：许可最宽松、网格与现有 demo 里 <svg viewBox="0 0 24 24"> 一致、体积实测已达标（4.9KB gzip 对图标库而言极小）、可单文件取用符合仓库去中心化原则。

    4. 推荐方案细则

    4.1 目录与产物（一个源，三种产出）

    packages/base/icons/                 # 唯一真源：一个语义一个文件
  check.svg
  chevron-down.svg
  ...
  index.json                         # 语义名 → 分类 / 是否 P0 / 替代名

dist/                                # 构建产出（不进 git）
  cinder-icons.svg                   # ① sprite：<symbol id="cin-i-check">
  icons/check.svg                    # ② 单图标文件：<img src> / CSS url() 直取
  cinder-icons.css                   # ③ 可选：.cin-i-check 类（data URI 内联，供伪元素用）
  cinder-icons-manifest.json         # 清单：名字、分类、原始字节、gzip

    三种产出对应用户的三种真实用法：

    用法 写法
    HTML 内图标（主路径） <svg class="cin-icon" aria-hidden="true"><use href="#cin-i-check"/></svg>
    伪元素 / select 箭头（CSS 内） background-image: url("icons/chevron-down.svg") 或 .cin-i-chevron-down 类
    独立使用（不引整套） <img src="icons/check.svg" alt="">（着色需用 mask，img 无法 currentColor）

    4.2 注入机制（解决 file:// 与跨域）

    外部 sprite <use href="cinder-icons.svg#cin-i-check"> 在 file:// 与跨域场景会被浏览器拦（CORS / 同源限制）。因此提供 behaviors/icons.js（可选，约 1.2KB）：

    1. 页面存在 <svg data-cin-icons> 挂载点时，Cinder.icons.mount() 拉取 sprite 后内联注入 DOM，此后同文档 #cin-i-check 引用一律可用；
    2. 无 JS 时：<use> 仍指向同文档 id（宿主自行内联 sprite 亦可），或退回使用 cinder-icons.css 的类方案；
    3. 已内联过则用 dataset.cinIconsReady 防重复注入（与现有行为层同一约定）。

    降级顺序：内联 sprite（JS）→ 宿主内联 sprite（无 JS）→ CSS 类 data URI（无 JS、无 sprite）→ 文字/aria-label（最终兜底）。

    4.3 命名与 API

    • 语义名：kebab-case，动词优先（check、chevron-down、arrow-left、trash、circle-alert）；
    • symbol id：cin-i-<name>（带前缀，避免与宿主页面自己的 sprite 撞名；104 个图标多花约 0.5KB，值得）；
    • 尺寸：复用 .cin-icon 的 data-size="sm|md|lg"，不新增尺寸体系；
    • 颜色：stroke: currentColor，继承文字色，不提供独立颜色 API；
    • 描边：默认 stroke-width: 2，暴露 --cin-icon-stroke 可覆盖（小尺寸 12–14px 时可调到 1.75）；
    • 可访问性：装饰性图标 aria-hidden="true"；承载语义时用 role="img" + aria-label，与 docs/ACCESSIBILITY.md 第 4 节一致。

    4.4 起步清单（104 个，四组）

    组 数量 举例
    状态与反馈 18 check circle-check circle-x triangle-alert circle-alert info circle-help loader-circle circle-dot shield-check
    方向与导航 12 chevron-down/up/left/right arrow-up/down/left/right arrow-left-right menu panel-left
    操作 32 search plus minus x pencil trash-2 copy save upload download refresh-cw filter sort（用 arrow-up-down）share-2 undo-2 redo-2 zoom-in/out external-link log-in/out
    对象与业务 42 user users building-2 house package boxes truck warehouse barcode scan-line qr-code tag receipt credit-card banknote file-text folder printer calendar clock chart-bar chart-line table layout-grid database server key lock

    实测：104 个 sprite 原始 20.3KB / gzip 4.9KB，均摊 48B；单图标文件 300–550B；单处 HTML 引用写法 69B。

    4.5 构建与闸门（接入 build.mjs 第 9 节）

    闸门 规则
    真源校验 icons/*.svg 必须 viewBox="0 0 24 24"、无 fill 硬编码颜色、无 <script>/on* 属性、路径节点只允许 path/circle/rect/line/polyline/polygon
    命名校验 文件名 kebab-case；index.json 必须覆盖全部文件，反向不得有多余条目
    体积闸门 sprite gzip ≤ 32KB 为软告警线（当前 4.9KB，余量 6.5 倍）；不进 entry 预算冻结阀——图标是独立资产，不参与 8KB 入口考核
    缺失拦截 组件 CSS/HTML 引用 #cin-i-xxx 或 url(icons/xxx.svg) 而真源无此文件 → build --check error（防止引用幻觉）
    许可 sprite 与单文件头部保留 ISC 版权注释；新增 docs/THIRD-PARTY.md 记录来源与版本号

    4.6 验收（scripts/acceptance-icons.mjs）

    1. sprite 内 symbol 数量 = icons/ 文件数；
    2. 每个 symbol 在 24×24 内有实际绘制（getBBox 非空，防止空壳图标）；
    3. <use> 渲染后 currentColor 生效：父元素设 color: red，图标像素采样为红（Playwright 截图取色）；
    4. 三档尺寸渲染高度分别等于 sm/md/lg 令牌值；
    5. prefers-reduced-motion 下 loader-circle 静止；
    6. 无 JS 场景：宿主内联 sprite 后图标可见（截图非空白）。

    4.7 迁移计划（分两批，不一次性翻 8 处）

    批次 范围 风险
    第一批：新增 HTML 用法 demos/ 里字符 ⌕ 与散落 <svg> 换成 #cin-i-*；新增 demos/icons.html 全量清单页 低（只加不改）
    第二批：替换组件内 data URI disclosure / details / option-group / controls / copytarget / fileinput 共 8 处 中：data URI 变长/变短都会触及 entry 预算冻结阀，必须逐处测字节，涨则按第 4 节流程显式改基线

    第二批之所以不并进第一批：这 8 处是 16 网格手绘图形，换成 24 网格图标存在视觉位移（箭头位置、勾的角度），必须一页一页比对截图，不能批量替换。

    5. 决策点（需确认）

    # 决策 选项 我的建议
    D1 图标来源 A Lucide（ISC）/ B 自绘 / C 图标字体 A：许可干净、体积已实测达标、可单文件拷贝
    D2 交付形态 A sprite + 单文件 + CSS 类（三种）/ B 仅 sprite / C 仅 CSS mask A：三种用法各有真实场景（HTML / 伪元素 / 独立）
    D3 起步清单范围 A 104 个（覆盖 60 组件常用位）/ B 先 40 个核心再增量 / C 全量 1600+ 提前囤 A：够用且不囤积；按组件真实需要增量，禁止预囤
    D4 是否替换现有 8 处 data URI A 第二批统一替换 / B 保留现状只做新增 A，但单独一批、逐处测字节
    D5 描边默认值 A 2px（Lucide 原值）/ B 1.75px（小尺寸更细腻） A，用 --cin-icon-stroke 覆盖，不偏离上游

    确认后执行顺序：真源落库 → 构建第 9 节闸门 → sprite/单文件/CSS 三产出 → icons.js 注入 → 验收脚本 → demos/icons.html → 迁移第一批 → （另一批）替换 8 处 data URI。

    6. 风险

    风险 说明 措施
    网格不一致 现有 8 处是 16 网格手绘，新图标 24 网格，混用会出现粗细/位置差 第二批逐个截图比对，不批量替换
    sprite 命名冲突 宿主页面若已有同名 #check symbol 统一 cin-i- 前缀
    file:// 限制 外部 <use href="file.svg#id"> 被拦 icons.js 注入内联，或宿主内联 sprite
    许可署名遗漏 ISC 要求保留版权与许可声明 产物头注释 + docs/THIRD-PARTY.md + 构建闸门检查
    图标囤积 提前收 1600 个图标导致产物臃肿、维护无主 清单按组件真实引用反推，index.json 标注 usedBy，无引用者不收录
