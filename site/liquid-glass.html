    一、素材判定

    项 内容
    素材形态 小红书/公众号图文，介绍 CruxGarden/plasma-ui
    它是什么 基于共享 WebGL 画布的 React 组件库：每块面板共享同一片等离子体材质，拖动时面板相互碰触会融合，能折射背景内容，松手吸附到网格或邻边
    内置能力 拖拽 + 网格/邻边吸附；三种 mood（tidal / aurora / ember）与自定义；可调折射、霜化、着色、边缘光、颗粒、辉光、弹簧动效
    组件范围 仅容器类：面板、停靠栏、卡片、对话框；另有 5 个基础件：按钮、开关、滑块、标签页、手风琴；其余组件应当嵌套在容器内部使用
    它自述的限制 适用于电脑端浏览器；每帧全屏渲染，手机上会很吃力
    它自带的降级 WebGL2 不可用时退到 CSS 霜化面板；服务端渲染出静态标记，水合后再接画布
    生态旁证 第三方评测与社区讨论普遍认可技术质量，但认为"液态玻璃作生产级 UI 范式"性价比差；SVG 位移贴图做真折射的方案目前仅 Chromium 的 backdrop-filter 可用，且动态更新性能代价大

    结论：素材的价值不在"这套组件"，而在它给出的视觉语言与它的降级路径。前者可吸收，后者恰好印证 Cinder 的 CSS 优先路线是对的。

    二、与 Cinder 现行纪律的冲突矩阵

    Cinder 纪律 plasma-ui 的做法 冲突判定
    CSS 优先，删 JS 退化语义标签 无 WebGL2 即失去主体材质；React 组件是唯一用法 硬冲突
    去中心化自包含单文件 全屏共享画布 + Provider 上下文，组件不可独立取用 硬冲突
    手机端可用（通用库须覆盖移动浏览器） 官方明示手机上很吃力 硬冲突
    单入口 gzip ≥7KB 逐字节冻结 引入 WebGL 运行时与着色器 硬冲突
    无 JS 时视觉不塌 依赖 canvas 渲染整块背景 硬冲突

    因此不整体引入 plasma-ui，只做选择性吸收。以下为吸收边界。

    三、三层拆解：收什么、弃什么

    3.1 视觉层（收）

    特征 吸收方式 实现载体
    半透明毛玻璃底 backdrop-filter: blur() saturate() + 半透明 tint 纯 CSS
    边缘高光（rim） 双层 inset 描边（外亮内暗）+ 顶边渐变亮线 纯 CSS
    背景透光着色 color-mix() 混背景语义色，非硬编码 rgba 纯 CSS + 令牌
    颗粒感（grain） 内联 SVG feTurbulence 作低透明度底纹，或 1×1 噪声 data URI 纯 CSS（≤300B）
    柔光投影 双层阴影（近距硬 + 远距散） 纯 CSS 令牌
    三种 mood 映射为 3 组 glass 预设（data-mood="tide|aurora|ember"），不叫 mood，叫 data-tint 3 组令牌

    3.2 交互层（半收）

    特征 判定 方案
    面板拖拽 收 库内已有 splitpanel、drawer 拖拽逻辑，复用既有行为，不新写拖拽引擎
    释放吸附网格/邻边 收（可选增强） 优先 CSS：容器 scroll-snap + 吸附点；确需自由拖拽时给 40 行内的 initGlassDock()，不跑就静态可读
    碰触融合（plasma blend） 弃 需共享材质与逐帧混合，本质是 WebGL；CSS 无法等价，硬做只会变成"假动画"
    折射背景内容 弃（真折射） 见 D3；只有 backdrop-filter 里塞 SVG 位移贴图能近似，仅 Chromium，动态代价高；降级方案是模糊而非折射
    弹簧动效 部分收 玻璃层只给"出现/收起"用 cubic-bezier 近似弹簧；prefers-reduced-motion 直接归零

    3.3 架构层（弃）

    React 组件模型、Provider 上下文、WebGL 运行时、共享画布材质——全部不吸收。Cinder 的玻璃能力必须是一个 CSS 文件 + 一个 data 属性就能生效，删掉 JS 后仅失去吸附与拖拽，视觉不塌。

    四、落地方案：base/glass 可选入口

    4.1 文件与 API

    packages/base/src/glass/glass.tokens.css     # 4 组色系 × 6 个变量，含暗色与高对比覆盖
packages/base/src/components/glass.css       # 材质本体 + 降级阶梯，约 260 行
packages/base/src/intents/glass.md           # 意图契约（负责/不负责/状态机）
demos/glass.html                             # 演示页：容器矩阵 + 降级对照
scripts/acceptance-glass.mjs                 # 静态契约验收，纳入 acceptance-all
dist/entries/base/glass.css                  # 构建产出的按需入口（预估 gzip 2.5–3.5KB，<7KB 只记录不冻结）

    用法（不新增重复组件，只给现有容器加一层材质）：

    <article class="cin-card" data-surface="glass">…</article>
<div class="cin-dialog-panel" data-surface="glass" data-tint="aurora">…</div>
<header class="cin-toolbar" data-surface="glass" data-glass="none">…</header>  <!-- 局部反选 -->

    4.2 令牌（新增 6 个，全部带 --cin-glass- 前缀，不覆盖既有令牌）

    令牌 缺省 说明
    --cin-glass-blur 16px 模糊半径，移动端降为 10px
    --cin-glass-sat 1.4 饱和度增益
    --cin-glass-tint color-mix(in oklab, var(--cin-color-bg-surface) 62%, transparent) 底色，随语义表面走
    --cin-glass-rim color-mix(in oklab, #fff 26%, transparent) 边缘高光
    --cin-glass-grain 0.035 颗粒不透明度
    --cin-glass-shadow 双层阴影组合值 柔光投影

    三档 data-tint：tide（青绿，缺省）、aurora（紫蓝）、ember（暖橙），只用 color-mix 调 tint 与 rim，不改结构。

    4.3 降级阶梯（四级，逐级可用）

    级别 条件 表现
    L1 真玻璃 支持 backdrop-filter 且 color-mix 模糊 + 饱和 + 双层 rim + 颗粒
    L2 伪玻璃 不支持 backdrop-filter（@supports not） 半透明实色底 + inset 高光，无模糊，可读性优先
    L3 无透明 prefers-reduced-transparency: reduce 或 forced-colors: active 退回不透明 --cin-color-bg-surface + 1px 边框，颗粒关闭
    L4 无 CSS 增强 浏览器极老 等同于 L3（底色与边框都在基础组件里，仍成立）

    4.4 性能与可读性硬约束（写进 intent.md 与验收脚本）

    1. 白名单渲染位：backdrop-filter 只允许出现在固定/悬浮容器上（dialog-panel、drawer、popover、toolbar、bulkbar、notice-bar）。列表行、虚拟滚动行、表格单元格、卡片网格中的每一项一律禁止——acceptance-glass.mjs 按选择器白名单扫描 backdrop-filter 出现位置，越界即失败。
    2. 同屏 ≤3 层：backdrop-filter 元素嵌套不得超过 2 层，文档写明，演示页提供"错误示范"对照卡。
    3. 文字不透明：玻璃层内文字色必须用不透明语义令牌，禁止半透明文字压在玻璃上。
    4. 动效收敛：玻璃层不进 transform 长动画；prefers-reduced-motion 下吸附与位移归零。
    5. 预算：新入口只记录不冻结（<7KB），不改 budget-baseline.json 中既有 62 个入口的任何字节；build --check 必须维持 0 error。

    4.5 与现有组件的挂靠关系（不新增重复组件）

    plasma-ui 的组件 Cinder 对应物 处理
    面板 Panel card / splitpanel 加 data-surface="glass"，不新建 panel
    停靠栏 Dock toolbar / bulkbar 同上
    卡片 Card card 同上
    对话框 Dialog overlay 内 .cin-dialog-panel 同上
    按钮 controls 的 .cin-btn 只允许 data-variant="glass" 用于浮层内，正文区域不用
    开关 / 滑块 controls / slider / range-slider 不加玻璃（可读性与命中区优先）
    标签页 tabs 只给 .cin-tabs 外层加玻璃，页签本体不加
    手风琴 disclosure 只给容器加玻璃，行内不加

    七、明确否决项

    • 引入 WebGL / 着色器 / 共享画布材质：与零依赖、单文件、移动端可用三条同时冲突。
    • React 组件包装：Cinder 是框架无关的 CSS + 原生 JS 行为层，包 React 意味着 8 套框架包装的维护成本。
    • 全屏每帧渲染：素材自己都标注手机上吃力，而 Cinder 作为通用库必须覆盖手机端浏览器，不能假设只有桌面用户。
    • 把玻璃做成"新组件"：会产生 glass-card / glass-dialog 类重复组件，与现有 64 个组件的语义层冲突，只做"材质属性"。

    按 AGENTS.md §3「四族 × 五档」登记为 D 档（不做）：WebGL 运行时、React 包装、全屏逐帧渲染、玻璃独立组件、碰触融合。后续若有人再提，直接引本节回绝，不再重复评估。
