    2.1 需关注项：controls 预算余量告急

    • 现状：8112 B / 8192 B，仅剩 80 B；相对基线 6680 B 已增长 21.4%，构建器给出 warning。
    • 风险：controls 入口再添任何样式（哪怕一条多值 box-shadow）都会顶穿上限，把 1.6.x 的补丁发布逼成一次拆包重构。
    • 建议（下一版本处理，不阻塞本次发布）：把 controls 中低频控件（如 input-number、currency-input 共用段）下沉为二级按需入口，或将大段 box-shadow / transition 收敛为令牌引用。

    2.2 视觉回归基线差异（环境性，非代码回归）

    • 本轮实测 npm run visual:check 关键 8 页 0/8 一致：icons 3.36% / erp-dashboard 2.54% / overlay 2.16% / approval-card 1.57% / tool-chips 0.81% / thinking 0.74% / base 0.59%（阈值 0.20%），skins 页尺寸 1280×1661 → 1280×1657。
    • 判定依据：① 本轮治理仅改文档与 demos/index.html，8 个关键页均未被改动；② tests/visual/diff/ 存有 11-03 的 index.diff.png 历史差异，非本轮新现象；③ 差异形态为 0.2%–3.4% 量级的整体渲染微差，与浏览器 / 字体渲染环境差异特征一致。
    • 处置：同步视觉基线（tests/visual/baseline/）或对齐渲染环境后重跑即可转绿；不阻塞代码发布。
    • 口径备查：审计时点曾核到 126/126 的合并口径，当前环境以 68 组脚本分组为准。

    3. 四态观测（默认 / hover / active / focus-visible / disabled）

    统计口径：按 packages/base/src/components/*.css 与 packages/erp/src/blocks/*.css 单组件文件统计，不含 dist 入口（入口把基座一起打包，会把 80 个入口全部误判成含 button 规则），也不含 .tokens.css。

    观测项 数值
    组件样式文件 78（base 72 + erp 6）
    含交互控件的组件 17
    有 hover 规则的组件 46
    有 active 规则的组件 9
    有 focus-visible 的组件 40
    有 disabled 规则的组件 24
    焦点态 由 packages/base/src/base.css 全局 :focus-visible 统一提供（2px accent 轮廓 + 2px offset），组件内另有 40 处细化

    关于 hover / active 数字偏低的说明（避免误读）：

    • 组件常复用共享基类选择器（例如 cascader 的悬停实际由 components/controls.css 的输入框规则承担），按单文件统计会记成「缺 hover」，渲染上并不缺。
    • 因此这两项只作观测、不作阻断；唯一硬项是「基座是否提供全局焦点态」，本版已确认提供。
    • 若后续要升级成阻断闸门，需先在浏览器里对 17 个交互组件做真实悬停采样，再按白名单收敛，不能直接拿本表当缺陷清单。
