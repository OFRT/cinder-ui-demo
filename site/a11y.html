    1. 承诺层级

    Cinder 只对以下四类事项做承诺。不在此列表内的，视为未承诺。

    层级 承诺内容 兑现方式
    语义优先 能用原生元素的，一律用原生元素（button / input / select / table / details / dialog），不自造 div 控件 组件 CSS 只做外观与状态，语义由 HTML 承担
    角色齐全 复合控件补齐 role + aria-*，状态变化同步属性 见第 2 节实测数据
    键盘可达 交互组件支持 Enter / Space / Esc / 方向键 / Home / End / Tab 中的适用项 见第 3 节
    动效可降级 所有动画在 prefers-reduced-motion: reduce 下关闭或退化为静态 49 个 CSS 文件 + 9 个 JS 行为含降级分支

    不作承诺的部分：屏幕阅读器逐款实测（NVDA / JAWS / VoiceOver 组合矩阵）、WCAG AA 逐条认证、第三方审计报告。这些需要外部测试，当前无预算。

    2.1 焦点与键盘的既有约定

    • 焦点环走 --cin-color-focus-ring 令牌，禁止组件自定颜色，保证全局一致且随主题/暗色切换。
    • 浮层类（dialog / popover / command-palette / cascader）使用焦点陷阱 + Esc 关闭 + 关闭后焦点回到触发元素。
    • 列表类复合控件使用 roving tabindex 或 aria-activedescendant（二者在同一组件内不混用）。
    • 树、网格、轮播、分段控件补齐方向键与 Home / End。

    2.2 非颜色编码

    状态不单靠颜色传达：危险态同时改边框样式与 aria-invalid；选中态同时改 aria-selected / aria-checked；必填项用文字或 required 属性而非仅红色星号。

    3. 已知缺口（如实列出）

    缺口 影响 计划
    无 axe-core 自动化扫描 结构性问题只能靠人工与验收脚本，覆盖不全 P1 待做（接入 CI，断言"零 serious"）
    无逐组件键盘矩阵文档 每个组件支持哪些键位散落在 intents/<name>.md 第三段，没有汇总表 P1 待做（从 60 份 intent 汇总生成）
    屏幕阅读器未实机验证 实际朗读顺序可能与预期有偏差 无预算，列为不承诺项
    对比度未自动化校验 依赖令牌取值人工把关，浅色/暗色各 8 套皮肤可能有个别不达标 P2 待做（令牌层校验）
    sr-only 工具类仅 1 处定义 需要视觉隐藏文本的场景覆盖薄弱 随组件补齐

    任何缺口修复后必须同步更新本表，不允许"改了代码不改声明"。

    4. 使用方需要注意的两件事

    1. 不要移除原生语义。Cinder 的 CSS 以 [data-*] 属性做状态，不改标签名。用 div 替换 button 会直接失去键盘与朗读能力。
    2. 图标必须有可读名。.cin-icon 只是容器，装饰性图标加 aria-hidden="true"，功能性图标必须配 aria-label 或可见文字。
